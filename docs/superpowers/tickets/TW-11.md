# TW-11 — Implement HistoricalDataQueue and 30-day Kbars chunking

**Goal:** Centralize Shioaji historical calls with bounded chunks, de-duplication, rate limiting, retries and per-symbol isolation.

**Depends on:** TW-03, TW-04  
**Branch:** `tw-11-historical-data-queue`

## Files
- Create `backend/app/services/shioaji/kbars.py`
- Create `backend/app/services/historical_queue.py`
- Create `backend/tests/services/shioaji/test_kbars.py`
- Create `backend/tests/services/test_historical_queue.py`

## Interfaces produced
A queue API accepting `(AssetRef, start, end)` with explicit inclusive/exclusive date semantics and normalized minute OHLCV results.

## Work
- Split upstream requests so no Shioaji Kbars call spans more than 30 calendar days.
- De-duplicate identical in-flight ranges.
- Apply a conservative centralized rate limiter, bounded retry, and timeout.
- Failure for one symbol/range must not abort unrelated work.
- Keep queue independent from DB persistence (TW-12 owns persistence).
