# TW-14 — Implement SubscriptionManager and Shioaji live SSE ingestion

**Goal:** Maintain one Shioaji live stream and reconcile the desired 180-slot set through subscribe/unsubscribe diffs.

**Depends on:** TW-07, TW-10, TW-13  
**Branch:** `tw-14-subscription-manager`

## Files
- Create `backend/app/services/shioaji/stream.py`
- Create `backend/app/services/subscription_manager.py`
- Create `backend/app/services/live_quote_store.py`
- Create tests under `backend/tests/services/shioaji/` and `backend/tests/services/test_subscription_manager.py`

## Interfaces produced
- `LiveQuoteStore`: per-symbol latest Quote + freshness + listener/async subscription API.
- `SubscriptionManager.reconcile(wanted)` calculating subscribe/unsubscribe diff.

## Work
- Keep one long-lived upstream SSE connection.
- Never exceed 180 operational subscriptions.
- Subscribe/unsubscribe only set differences; no relogin on view changes.
- On upstream reconnect, recompute wanted set and restore subscriptions.
- Update LiveQuoteStore on events; mark data disconnected/cached explicitly on failures.
- Fake SSE server in tests.

## Verification
Run subscription manager, stream reconnect, and quote mapping tests.

## Acceptance
- [ ] Diff operations exact and idempotent.
- [ ] Reconnect rebuilds desired set.
- [ ] No >180 state occurs.
- [ ] LIVE/CACHED/DISCONNECTED transitions are test-covered.
